# Демо и сабмит

## Сценарий на 2 минуты

Заполнить под свою Задачу в первые 30 минут, до написания кода. Один сценарий, не три.

1. **Проблема, 15 с.** «<Кто> тратит <сколько> на <что>, потому что <почему>.» Цифра обязательна.
2. **Запуск, 10 с.** Вставляем реальный материал → «Запустить агента».
3. **Агент работает сам, 40 с.** В журнале видно: сам выбрал инструмент → получил данные →
   сам решил, что проверить дальше. Это главное отличие от чат-бота — покажите его явно.
   Если в материале есть строка, пытающаяся управлять агентом, — обратите на неё внимание жюри:
   агент обошёлся с ней как с данными.
4. **Человек в контуре, 20 с.** Агент доходит до действия, меняющего внешнюю систему,
   и останавливается. Нажимаем «Разрешить».
5. **Результат, 20 с.** Отчёт: итог, доказательства, что сделано, что дальше.
   Назовите цифру: сколько времени/денег это экономит.
6. **Что дальше, 15 с.** Интеграции, кто заказчик, как масштабируется.

Критерии Demo Day (п. 5.7.2): ценность 25, результат и качество 20, инновационность 15,
потенциал 20, презентация 20. **65 из 100 — не про код.** Репетируйте пункты 1, 5 и 6.

## Перед сабмитом

Первые четыре пункта — условия допуска, а не пожелания.

- [ ] Проект запускается с **чистого `git clone`** строго по README, на ноуте, где его не писали (п. 5.4.15–16)
- [ ] `docker compose up --build` работает **без `.env`** и без ключей (п. 5.6.6)
- [ ] `python scripts/verify.py` печатает `OK`
- [ ] README заполнен по всем разделам, включая «Использованные сторонние компоненты»
      и «Что было готово до начала соревновательной части» (п. 5.4.4, 5.4.4.2)
- [ ] `make check` зелёный
- [ ] `docs/HOURLY.md` заполнен за все пять часов, теги `h1`–`h5` запушены (п. 5.4.8)
- [ ] У всех троих есть коммиты под своим именем (п. 4.6)
- [ ] Видео-демо записано и лежит по ссылке — страховка от упавшего деплоя
- [ ] Развёрнуто по публичной ссылке, ссылка открывается с телефона, QR готов для слайда
- [ ] Ключи не в репозитории; если нужен настоящий ключ — подготовлен отдельный тестовый доступ
- [ ] Примеры данных реалистичны, казахстанский контекст — плюс
- [ ] Всё запушено **до 18:00**: то, что зафиксировано на этот момент, и есть итоговая версия (п. 5.4.13)
