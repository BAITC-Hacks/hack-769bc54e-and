# Как работать втроём и не мешать друг другу

## Роли (зоны владения = меньше merge-конфликтов)
| Кто | Владеет | Главный результат |
|---|---|---|
| A — агент | `backend/agent/core/domains/`, `core/prompts.py`, evals | инструменты и качество ответов на реальной модели |
| B — продукт | `frontend/`, `backend/agent/views.py`, `lib/types.ts` | демо, которое понятно за 30 секунд |
| C — капитан: данные, демо, сабмит | `docs/`, README, данные домена, видео, слайды | проект, который запускается у чужого человека |

Чужую зону трогаем только через владельца («добавь поле X в ответ API»).
Контракт API меняет только B — `views.py` и `types.ts` правятся одним коммитом.

## До площадки, накануне
- `git config user.name` и `user.email` на всех трёх ноутах — под данные регистрации.
  Вклад каждого проверяют эксперты и жюри (п. 4.1, 4.6).
- SSH-ключ или PAT к GitHub настроен и проверен пушем в тестовый репозиторий.
- `make setup`, `make check`, `make verify` прошли локально у каждого.
- Зависимости скачаны заранее: `npm ci`, `pip install`, `docker compose build`.
  Wi-Fi на 2500 человек — не инфраструктура.

## Git
- В 13:00 первым делом: все трое клонируют репозиторий организатора и делают по пустяковому
  коммиту — убедиться, что права на пуш есть у всех. Дальше вся работа только там (п. 5.4.9).
- `main` всегда запускается. Прямые коммиты в `main`, ревью post-factum: на пять часов
  цикл через PR не окупается. Ветка — только под рискованный эксперимент.
- `git pull --rebase` перед каждым пушем. `--force` на `main` запрещён.
- **Каждый час на отметке :50:** `make check` → коммит → пуш → строка в `docs/HOURLY.md`
  → `git tag h<N> && git push --tags`. Будильники на 13:50, 14:50, 15:50, 16:50, 17:50.
- Парное программирование — `Co-authored-by: Имя <email>` в сообщении коммита.
- Сообщения коммитов осмысленные: историю читают технические эксперты и AI-судья (п. 4.2).

## Работа с AI-инструментами
Разрешены любые (п. 5.4.12), Codex не обязателен. Что работает на практике:
- Одна задача на запуск, с критерием готовности: «добавь инструмент X, тест Y должен пройти,
  `make check` зелёный».
- Параллельные задачи — в разных ветках/worktree и в разных папках.
- Читайте дифф до коммита. Агент быстро пишет и так же быстро ломает соседнее.
- Чем пользовались — записывайте сразу в раздел README «Использование AI-инструментов»,
  в конце дня вспоминать будет некогда.

## Площадка
- Уходить нельзя: суммарно не более 60 минут отсутствия и только с разрешения организатора
  (п. 5.1.7.1). Еда и вода — с собой, перерывы по очереди.
- Своё: ноутбуки, зарядки, **переходник с LAN у каждого**, тройник, мышь, повербанк (п. 5.2.8).
