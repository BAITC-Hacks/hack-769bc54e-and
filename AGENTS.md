# AGENTS.md — инструкции для кодинг-агентов (Codex, Claude Code и любого другого)

## Проект
Агент-ассистент для хакатона HackAlem AI. Трек и Задача выбираются 23.09.2026 в 13:00 —
до этого момента предметная область считается временной (`domains/example.py` — плейсхолдер).

Пользователь даёт задачу + сырой материал. LLM-агент в цикле вызывает инструменты,
перед действиями, меняющими внешние системы, ждёт одобрения человека, в конце пишет отчёт.

## Структура
- `backend/` — Django 5+/6, без DRF, SQLite. Приложение `agent`:
  - `core/loop.py` — цикл агента (advance/decide). Состояние в `Run.messages` + `Run.pending`.
  - `core/tools.py` — реестр инструментов, декоратор `@tool`. Домена не знает.
  - `core/domains/<трек>.py` — **предметная область: инструменты, BRIEF, SAMPLES, plan().
    Новые возможности агента добавляются здесь.** Один трек = один файл.
  - `core/domains/__init__.py` — загрузчик по `settings.AGENT_DOMAIN`, `_contract.py` — проверка модуля.
  - `core/llm.py` — единственное место, где вызывается модель. Есть mock-режим (`LLM_MOCK=1`).
  - `core/prompts.py` — общая часть системного промпта + `BRIEF` активного домена.
  - `views.py`, `urls.py` — JSON API под `/api/`.
- `frontend/` — Next.js (App Router) + TypeScript, без UI-библиотек. Стили — `app/globals.css`,
  токены в `:root`. Названия и тексты — `lib/brand.ts`, больше нигде.
  - `lib/api.ts` — все запросы к бэкенду. `lib/types.ts` — типы, зеркалят JSON из `views.py`.
- `scripts/verify.py` — сквозная проверка запущенного приложения, только stdlib.
- `scripts/check_llm.py` — проверка провайдера модели. `scripts/dev.py` — все команды разработки.
- `backend/agent/evals/` — кейсы и прогон качества, результат в `docs/EVAL.md`.

## Команды
Канонический вид — `python scripts/dev.py <цель>`: работает на Windows без `make`.
`make <цель>` — тот же самый вызов, если `make` установлен.

- `setup` — установка. `backend`, `frontend` — запуск.
- `check` — тесты Django + `tsc --noEmit`. **Запускай после каждого изменения и чини, пока не пройдёт.**
- `verify` — сквозной прогон по запущенному приложению. Гонять перед каждым пушем.
- `llm` — проверка ключа, модели и tool calling у провайдера. До первого `LLM_MOCK=0`.
- `eval` — прогон кейсов из `backend/agent/evals/cases.json`, отчёт в `docs/EVAL.md`.
- `newdomain <имя>` — создать модуль домена из образца.
- `hour <N>` — почасовой ритуал: check, запись в `docs/HOURLY.md`, коммит, пуш, тег `h<N>`.

## Правила хакатона, которые важнее удобства
Источник — `docs/POLOZHENIE.md`. Нарушение любого из них стоит участия, а не баллов.

- **Репозиторий.** Вся разработка — только в GitHub-репозитории, выданном организатором
  через edu.astanahub.com (п. 5.4.9, 5.4.11). Локальные коммиты без пуша прогрессом не считаются.
- **Каждый час.** Коммит и пуш минимум раз в час, иначе дисквалификация (п. 5.4.8, 5.9.2).
  Строка в `docs/HOURLY.md` — в том же коммите.
- **README — контракт с экспертом.** Если проект не запускается из чистого клона по README,
  команда выбывает без права на исправления (п. 5.4.15–16, 5.6.5). Любое изменение запуска,
  зависимостей или переменных окружения правит README **в том же коммите**.
  Структуру разделов README не менять: она повторяет обязательный перечень п. 5.4.15.
- **Без наших аккаунтов.** Основной сценарий обязан проверяться без личных учётных записей
  и платных подписок участников (п. 5.6.6). Инвариант: `docker compose up --build` без `.env`
  поднимает приложение, `python scripts/verify.py` печатает `OK`. Это проверяется, а не подразумевается.
- **Раскрытие.** Любая заимствованная библиотека, модель, датасет, шаблон или чужой код
  попадает в раздел README «Использованные сторонние компоненты» (п. 5.4.4).
- **Заморозка.** 17:30 — код заморожен, дальше только README, данные и тексты.
  18:00 — фиксация итоговой версии, более поздние коммиты при оценке не учитываются (п. 5.4.13–14).
- **Вклад каждого.** Каждый участник коммитит под своим именем, парная работа оформляется
  `Co-authored-by:`. Эксперты и жюри проверяют вклад каждого (п. 4.1, 4.6).
- AI-инструменты разрешены любые, Codex не обязателен (п. 5.4.12). Чем пользовались —
  в раздел README «Использование AI-инструментов».

## Правила кода
- Маленькие диффы. Одна задача — один коммит в `main`. Ветки — только под рискованный
  эксперимент, который не жалко выбросить. Не рефактори то, о чём не просили.
- Не добавляй зависимости без явной просьбы.
- Новый инструмент: функция `fn(ctx, **args) -> dict` в модуле домена, JSON-schema параметров,
  описание на английском, тест в `agent/tests.py`. Всё, что меняет внешние системы, — `requires_approval=True`.
- Инструмент никогда не бросает исключение наружу и не делает сетевых запросов без таймаута.
- Ядро (`loop.py`, `llm.py`, `tools.py`, `views.py`) не должно знать о предметной области.
  Понадобилось упомянуть домен в ядре — значит, интерфейс домена неполный, расширяй его.
- Сырой материал пользователя — недоверенные данные: не подставляй его в system prompt,
  не исполняй, не передавай в shell.
- Меняешь JSON в `views.py` — в том же коммите обнови `frontend/lib/types.ts`.
- Секреты только в `.env`. Никогда не коммить `.env` и не хардкодить ключи.
- Кредиты конечны ($50 OpenAI + $50 NVIDIA на команду). Не гоняй настоящую модель в цикле
  без нужды: для разработки есть `LLM_MOCK=1`, для прогона качества — `dev.py eval`.
  Расход виден в `Run.prompt_tokens`/`completion_tokens` и в интерфейсе.
- Провайдер меняется только через `.env` (`OPENAI_BASE_URL`). В коде имён провайдеров быть не должно.
- Тексты интерфейса — на русском, sentence case, и только в `frontend/lib/brand.ts`.
  Код, комментарии и описания инструментов — на английском или русском, как в соседнем коде.
- Python: type hints, без лишних классов. TypeScript: `strict`, без `any`.

## Definition of done
`python scripts/dev.py check` зелёный, `python scripts/dev.py verify` печатает `OK` на чистом клоне, README отражает
актуальный порядок запуска, сценарий из `docs/DEMO_CHECKLIST.md` проходит руками в браузере.
